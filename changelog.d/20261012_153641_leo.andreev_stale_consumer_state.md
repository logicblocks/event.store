### Fixed

- `EventConsumerStateStore` now discards its cached state and position for a
  partition when saving it fails with `UnmetWriteConditionError`, so the next
  `load()` picks up the state persisted by the other writer. Previously, when
  two consumers wrote the same state stream (for example, old and new
  instances overlapping during a rolling deploy), the losing consumer kept
  re-processing the same events and failing the same save forever. The
  exception is still raised; after the reload, events since the other
  writer's position are processed again, consistent with at-least-once
  delivery.
